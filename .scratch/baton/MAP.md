## Destination

can be written and run — built on what Claude Code 2.1.268 already provides (`--bg`,

- **Facts established while charting**, so no session re-derives them:
  - CLI: `--bg/--background` starts a session in the background and prints an id that
    `attach`, `logs`, `stop`, `rm` take; `--bg --resume <id>` continues a session under the
    same id, or starts a copy and says so if it is already running; `-n/--name` sets the
    display name (prompt box, `/resume` picker, terminal title); `-w/--worktree [name]`;
    `--model`; `--permission-mode` (acceptEdits, auto, bypassPermissions, manual, dontAsk,
    plan); `--session-id <uuid>`; `--fork-session`; `--append-system-prompt[-file]`;
    `--settings <file-or-json>`; `--remote-control [name]`; `--tmux` (needs `--worktree`);
    `-p/--print` with `--output-format stream-json` and `--input-format stream-json`.
  - `claude agents` is a fleet view that lists and dispatches sessions, with `--model`,
    `--permission-mode`, `--effort`, `--settings`, `--allow-dangerously-skip-permissions`
    for dispatched sessions. `claude agents --json` prints interactive *and* background
    sessions; the full field set is `cwd, kind, startedAt, id, state, pid, status,
    waitingFor, sessionId, name` (interactive rows omit some), with `state` ∈
    working/blocked/done/failed/stopped, `status` ∈ busy/waiting/idle, and `waitingFor`
    naming a permission prompt or "input needed" — nothing about the last message
    (`research/background-sessions.md` §3). `claude attach <id>` opens a background session in the terminal
    (`←` returns to the agent view, Ctrl+Z drops to the shell, the session keeps running);
    `claude logs <id>` prints recent terminal output; `claude stop <id>` keeps the
    conversation for a later `attach`; `claude respawn <id>|--all` restarts.
  - Transcripts: `~/.claude/projects/<cwd-slug>/<sessionId>.jsonl`, one JSON record per
    line; `type` is `assistant`, `user`, `attachment`, or metadata (`custom-title` is what
    `/rename` and `--name` write; also `ai-title`, `permission-mode`, `last-prompt`).
    Assistant records carry `message.stop_reason` (`tool_use` mid-turn, `end_turn` at the
    end) and typed `message.content` (`thinking`, `tool_use`, `text`).
  - Environment: Terminal.app (`TERM_PROGRAM=Apple_Terminal`); no tmux, no iTerm2;
    `Claude.app` (desktop) is installed. `~/.claude/settings.json` sets
    `permissions.defaultMode: auto` and configures no hooks; Reclaim has no
    `.claude/settings.json`. At charting, three Reclaim sessions were in flight
    (`M14` idle, `Milestone Model Audit` busy, `Live File Watch Design` busy).

## Out of scope

- **Baton doing milestone work.** It never edits a target project's code, runs its reviews
  (`/review-2` and `/address` stay inside the session), or makes its scope calls. Those
  belong to the sessions and to the human.
- **Cloud or remote execution.** Claude cloud sessions and remote triggers are not v1; Baton
  runs on this Mac.
- **Terminal-emulator automation as the mechanism.** Typing prompts into tmux, iTerm2 or
  Terminal.app is superseded by `--bg`; a tab that runs `claude attach` may survive as a
  viewing convenience under "Watching a dispatched session".
- **Anything multi-user, hosted or commercial.**
