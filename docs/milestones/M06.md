## Scope

Only enable multiple workers in one project after exclusive project integration is proved across processes. Introduce per-project integration leases and short journal critical sections without losing coherent decisions. Define resource observations and stale/unknown states explicitly. Account-wide usage percentages are telemetry, not a per-model guarantee. Do not remove the single-run-per-project guard until the replacement invariant is tested. Any cleanup command must be explicit and prove no live/pending owner and verified integrated work.

## Acceptance

Two close-outs never share an index or mutate the same canonical tree concurrently; main changing during checks prevents promotion; a failed integration does not corrupt another lane; cap includes uncertain and human-owned runs; stale quota data does not fabricate remaining capacity; no unfinished worktree is pruned.

Run sh tests/run.sh and add behavior assertions for the new transitions. Use fault injection at
new effect boundaries, not only snapshot comparisons. Use two independent reviews and address
concrete findings. No build, live session, launchd or target-project operation is implicit in the
fixture test suite. Obtain any required explicit authorization before a live acceptance action.


## Cross-layer acceptance

- F-43: explicitly revise F-09 when replacing the one-open-run policy. Distinguish durable runs
  from execution-resource leases; prove when a known-stopped worker may release a resource and
  why an uncertain launch still reserves capacity.
- Specify and test scheduling order and fairness for eligible projects under that policy. A
  repeatedly waiting project must not silently starve independent work, and fairness cannot
  override dependency, ownership or integration constraints.
- Exercise stale/unknown and account-wide quota observations. Do not infer a per-model budget or
  release a reservation from absent telemetry. Model changes follow explicit authorization.
- Run concurrent integration/failure cases against the replacement lease design before enabling
  more project workers; the old conservative limit stays until the new invariant is proved.

## Recovery procedure

Inspect existing code, durable action records, candidate work and prior evidence. Resume only the
unfinished part. Do not reset failure budgets, duplicate external effects, overwrite human work,
or weaken an invariant to make a continuation succeed. Split scope into a real plan row if needed.
