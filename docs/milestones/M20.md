# M20 — A rewritten history does not break a completion proof

## 1. Identity

- **ID:** M20. **Objective:** a completion whose recorded baseline was replaced by a history rewrite
  that kept every file identical is proved against that baseline's equivalent on the new history,
  instead of being rejected.
- **User-visible result:** after a message-only rewrite of a registered project's history, the
  lanes that were open across it complete and are consumed as usual; M15-c's parked handover,
  written again, is consumed.
- **Size:** Small, about 1–2 hours; high effort.

## 2. Dependencies and entry conditions

None in the plan. M15-c and M15-e are the two lanes this unblocks; neither needs to finish first.
`lib/completion.sh` is a file neither of them nor M19 edits.

## 4. Requirements, scope, non-goals

**The measured finding.** At 2026-10-01 16:00:42 `main` in the canonical checkout was reset to
`origin/wip-sync/main`, a rewrite that removed `Co-Authored-By` and `Claude-Session` trailers from
commit messages. All 287 commits kept identical trees, authors and dates; only their ids changed.
Baton's log records each dispatch's baseline by commit id. M15-c's attempts 1 and 2 recorded
`a24b372f1f407cbeef2805b77fb498e29a8330f9`, which is no longer an ancestor of `main`; its rewritten
equivalent `3f0e0c78` has the same tree. `completion_baseline` returns the *first* baseline recorded
on the branch across attempts, so M15-c's attempt 3 handover (`merged_as`
`aed2d5efd52f194363692b6006f4918faf134e18`) was rejected at 17:11:31 with rule `completion-chain`
and the lane parked `other`. M15-e's attempt 1 recorded `e953bbbb1d9b2a5ad189ca2b8aa46ebc93f41c1d`,
also replaced, so its handover will meet the same rule. No route through the relay recovers either:
the log is append-only, a redispatch keeps the first baseline, and a handover written again is
judged the same way.

**Scope.**

1. **The equivalent baseline.** In `completion_baseline`, or where its result is used, a recorded
   baseline that is not an ancestor of the claimed `merged_as` is replaced by the ancestor of
   `merged_as` whose tree is identical to it, when exactly one such commit exists. A tree equal and
   an ancestor is the rewrite's own image of the commit Baton recorded, so the claim stays bound to
   what was dispatched and the measured range still covers every attempt's work.
2. **Otherwise as today.** No equivalent (the baseline object is gone, or no ancestor shares its
   tree, or more than one does): refuse with `completion-chain` as now, and say why in the detail.
   Never fall forward to a later attempt's baseline: that would shrink the range the proof measures.
3. **The record says so.** The completion evidence names the recorded baseline, the equivalent used
   and why, so a proof across a rewrite is distinguishable from an ordinary one.
4. **A handover written again is consumed.** A `complete` artifact rejected before this lands and
   written again by its session afterwards is judged anew and consumed; prove it, because M07-d's
   "acted on once" rules were written for consumed handovers, not rejected ones.
5. **A setup fact.** `docs/SPEC.md`'s setup facts gain one line: a rewrite of a registered project's
   history that changes file contents orphans the recorded baselines and is refused; one that keeps
   every tree is followed.

**Non-goals.** No rewriting of Baton's log. No change to what a completion must prove beyond the
baseline's identity. No change to the planning lane's branch reuse (a separate gap, owned by a later
milestone). No live session.

## 7. Implementation checklist (ordered)

1. Reproduce the finding as a failing fixture: a fixture repository, a dispatch baseline, then a
   message-only rewrite (`git commit-tree` with the same trees), then a merge on the new history.
2. The equivalent baseline and its evidence; the fixtures for no equivalent and an ambiguous one.
3. The rejected-then-rewritten handover fixture.
4. SPEC, ARCHITECTURE, the decision; §8; review and close out.

## 8. Fixtures, verification, acceptance

Fixtures only, a fixed clock, fixture repositories; run each scenario twice and `sh tests/run.sh`.

- Baseline replaced by a message-only rewrite, merge on the new history: proved; the evidence names
  the recorded baseline and the equivalent; the range measured is the equivalent's.
- Baseline replaced by a rewrite that changed a file in it: refused `completion-chain`, the detail
  saying no ancestor shares the baseline's tree.
- Two ancestors share the tree (an empty commit beside it): refused, the detail saying ambiguous.
- A handover rejected for `completion-chain` under the old rule, then written again unchanged: one
  `consumed` `complete`.
- Every existing `completion-*` scenario unchanged.

## 9. Definition of done and evidence

The handoff template in `docs/MILESTONES.md`; the fixture traces; `sh tests/run.sh`'s scenario and
failure counts, read to completion. An unrun check is never reported as passed.

## 10. Risks and decisions this milestone settles

A tree match is exact for a message-only rewrite and refuses anything else, so it cannot launder a
completion that skipped the work. Record the decision at the next free D-number read from `main` when
it is written. Apply M19 §10, "Main advances while a session runs", in full: M15-e and M19 may merge
while this runs.
