# M01 — Plan reader and hand-run dispatch

## 1. Identity

- **ID:** M01. **Objective:** The smallest thing that can dispatch. Read a plan file as the
  tick will read it, and dispatch one milestone by hand — worktree, settings file, slot line,
  prompt sidecar, one `claude --bg`, one log line — so that M02 can be dispatched by Baton rather
  than by a person. Built by hand on `main`, because nothing exists to dispatch it.
- **User-visible result:** `baton plan Baton` prints this repository's graph as parsed and
  validates every `Model` cell. `baton dispatch Baton M02` creates `../Baton-M02` on branch
  `m02` from `main`, composes `~/.baton/settings/Baton-M02.json`, replaces the slot line in M02's
  prompt, writes the body to `~/.baton/prompts/<session>/1.txt`, runs `claude --bg` by absolute
  path with the worktree as `cwd`, arms `caffeinate`, and appends a `dispatch` event to
  `~/.baton/log.jsonl`. The three hooks fire inside the dispatched session from the installed
  relay. `sh tests/run.sh` runs every fixture without quota.

## 2. Dependencies and entry conditions

None. The founding document set is committed on `main` (the repository's first commit). The three
setup facts — the granted shell (REQ-SETUP-01), the `bypassPermissions` disclaimer
(REQ-SETUP-02, accepted on this Mac on 2026-09-11) and `cleanupPeriodDays` (REQ-SETUP-03, `3650`
on this Mac) — are the person's and are needed before the first hand-run dispatch, not before this
session starts. The prototype under `.scratch/baton/prototype/` is cited and read, never moved or
edited.

## 7. Implementation checklist (ordered)

1. The skeleton: `bin/baton` reads the four seams once, sources `lib/*.sh`, and dispatches the
   verb; every file starts `#!/bin/sh` and `set -eu`; `baton` with no verb prints the six verbs
   (four of them "not yet: M0n"). `install.sh` copies `bin/baton`, `lib/`, `hooks/` to
   `~/.baton/bin/`, copies `/bin/sh` to `~/.baton/bin/sh` if absent, creates the state directories
   and `config.json` with the defaults if absent, and is idempotent.
2. `lib/lock.sh`: `mkdir "$BATON_HOME/lock"` or exit; write `pid` and `at` inside; release on
   `EXIT` trap. Every verb enters through it.
3. `lib/log.sh`: the envelope (`at` from `BATON_DATE` in ISO 8601 with offset; `kind`; the four
   optional fields added only when given — build with `jq -n --arg … 'if $x != "" then . + {…}'`
   so an absent field is absent, never null); `log_event` composes one line with `jq -c`, asserts
   it is under 4 KB, and appends with one `printf '%s\n' >>` — the only place `log.jsonl` is
   written. `attempt_of` counts `dispatch` events for `(project, milestone)`. `sidecar_write`
   writes `prompts/<session>/<n>.txt` with `<n>` = existing files + 1 and prints the path and
   `shasum -a 256` of the normalised text. `prompt_normalise` is one function (see §10).
4. `lib/plan.sh`: find the milestone table by the first header cell `ID` and the gates table by
   `Gate`, wherever they sit; map columns by header name; split cells; parse tokens per
   REQ-PLAN-02, expanding ranges (`M01–M13`, en dash or hyphen) and accepting `–` for none; on any
   cell that does not parse, print `table`, `row`, `cell` and exit non-zero — the caller decides
   what that means. `plan_eligible` returns ids whose dependencies all read `done`, whose `Status`
   is blank, and which no uncleared gate holds. Test against this repository's own
   `docs/MILESTONES.md` and against Reclaim's (read only): Reclaim's parses once its migration
   adds the columns, and fails now with the cell named.
5. `baton plan <project>`: `project.json` → the plan file → the graph: one line per milestone with
   its state (done, eligible, held by which gate, blank), model, effort, remote; every `Model` cell

6. The hooks, cut from the prototype's three scripts with the observation writes removed:

   the `baton`-fence fallback; `stop-failure` writing the `api-error` artifact with `reason:
   api-error`, `error`, `error_details`, `detail`, `written_at`, `baton: 1`, `project` from
   `BATON_PROJECT` resolved to the canonical checkout; `statusline` writing the status file

## 10. Risks and decisions this milestone settles

- **The hash normalisation (item 45).** A trailing newline, a `\r\n`, or a stripped leading blank
  line handled differently on the two sides makes every one of Baton's own dispatches read as a
  takeover on the first night. Decide one rule — the recommendation is: strip one trailing newline,
  nothing else — apply it in `prompt_normalise` to both the sidecar text and (in M03) the
  transcript record's `message.content` text block, and prove it on the prototype's pair before
  writing it down.
- **The deny-rule forms for Baton's state paths.** The two classes are fixed; the forms are not.
  The prototype proved `Bash(sudo:*)` and the `osascript` mid-command wildcard bite under bypass;
  the `Read(//…)`, `Edit(//…)`, `Write(//…)` path forms were observed in `permission_suggestions`
  (a rule for `//Users/danny/.aws/**`) but never tested as denies. Write them, then prove one by
  hand in the item-12 session (ask it to append to `~/.baton/log.jsonl`) and record the result.
  If a form does not bite, say so in the evidence and leave the class covered by `CLAUDE.md`'s
  rule until M05.
- **`dispatch_failed` classification (item 47).** The four known stderr strings are from the
  binary; the streams and exit codes are not. Fill them from the item-12 capture, not from a guess.
- **`--effort`.** A top-level flag on `claude --bg`, restored by a flagless resume (`respawnFlags`
  on this Mac carries `--effort`); pass it only when the `Effort` cell is non-blank.
- **`prompt_from_brief` reads `main`, not the working tree.** A person mid-edit on a brief must not
  change what a dispatched session receives; `git show main:<path>` is the read.
- **Whether a `register` verb exists** is this milestone's call; `install.sh` writing Baton's own
  two files is the minimum, and a person writing Reclaim's by hand in M08 is the plan. Do not add
  the verb unless the install script cannot express it.
- **The worktree's transcript slug.** A session dispatched with `cwd` in `../Baton-M02` is slugged
  by the worktree path, so anything that finds a transcript must glob `~/.claude/projects/*/<session>.jsonl`.
  Nothing in M01 reads a transcript except item 45, but the sidecar path and the session id are
  what M02 and M03 will join on.
