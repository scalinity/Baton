# M12 — Plan generation from a repository

## 1. Identity

- **ID:** M12. **Objective:** turn the confirmed goal and a repository with no usable plan into
  a dispatchable milestone plan and self-contained briefs through a Claude Code session.
- **User-visible result:** onboarding a repository with no `docs/MILESTONES.md` produces a
  plan whose first milestone dispatches and completes, without a plan-approval conversation.
- **Size:** Large, about 5–7 hours; high effort. The cold end-to-end path is the substantial proof.

## 2. Dependencies and entry conditions

M11 complete and installed. Onboarding already resolves a Git project, derives its permissions,
confirms intent once and stores `goal`, `plan_format` and `onboarded_at` in its registration.
It adapts usable plans and identifies the no-usable-plan case; M12 implements that missing path.
Managed worktrees/grouping and baseline/scoped-change/Baton-check completion proof are installed.

## 3. Required reading

`CLAUDE.md`; `CONTEXT.md`; `CONTRACT.md`; `docs/v1.1/SCOPE.md` in full, especially §5 and §6 M12;
`docs/MILESTONES.md`; `docs/v2/01-findings.md` MILESTONE FORMAT in full; `docs/milestones/M07-d.md`
as the real format exemplar; `docs/SPEC.md` §2.1, §2.2, §2.6–2.8; `docs/ARCHITECTURE.md` §3,
§4.1–4.3, §7, §10; M11 completion evidence and its decision entries; current onboarding code,
`lib/plan.sh`, `lib/dispatch.sh`, `lib/inbox.sh`, `lib/candidates.sh`.

## 4. Requirements, scope, non-goals

- **Covers:** SCOPE §6 M12 and §8 items 1 and 7; extends REQ-CONTRACT and REQ-PLAN for generated plans.
- **Scope:** dispatch a cold Claude Code planning session using the stored confirmed goal and
  repository evidence; produce one plan graph, conforming briefs and initial handover; validate
  output before admission; run the first generated milestone through verified completion.
- **Non-goals:** approving the plan again, managed review sessions, a generic agent framework,
  direct model APIs, implementing the scope guard (M15-c) or completing a whole chain here (M13).

## 5. Expected files (proposed)

New `lib/planning.sh` and a repository-local planning prompt/template if needed; narrow changes
to the M11 onboarding module and `lib/dispatch.sh`; `tests/scenarios/plan-generate-*`;
`docs/SPEC.md`; `docs/ARCHITECTURE.md` §10 row M12; `docs/DECISIONS.md`; this brief and successor
prompt refreshes. Outside this repository: planning sessions/worktrees/evidence under
`$BATON_HOME` and the target's generated plan, briefs and contract instructions in that target.

## 6. Interfaces

- **Introduces:** the no-plan generation path, its repository/goal prompt, validation of its
  returned plan and briefs, and `plan_format: generated` on successful adoption.
- **Consumes:** M11's stored goal and no-plan result; `claude_bg <worktree> <name> <model>
  <effort> <settings> <prompt>`; existing hooks, mailbox and completion checks; plan parsing and
  candidate selection. Model judgement runs in a CLI session, never inline in the tick.

## 7. Implementation checklist (ordered)

1. Trace M11's no-plan path and add fixtures for absent/unusable plans, stored goal missing,
   and a resumable generation attempt. Do not reconfirm a goal already confirmed.
2. Write the planning prompt from repository evidence and the stored goal. Require the exact
   11 numbered sections and three unnumbered headings from MILESTONE FORMAT; each generated
   brief must contain its own context, Size, scope, acceptance and seven-part kickoff block.
3. Require token-only plan cells per CONTRACT clause 2, blank pending Status, real dependencies
   and no new approval gate. Require exact Completion evidence/Copy-ready session prompt
   headings, the verbatim slot paragraph, close-out proof and explicitly named successors.
4. Dispatch the planning session through the existing subscription CLI seam and hooks. Adopt
   only output that parses and conforms; return correctable defects to the generation path with
   concrete diagnostics. Preserve partial work on a resume instead of generating a second graph.
5. Publish the generated plan/briefs through the target's normal Git close-out and seed the
   initial runnable names automatically. Expose the adopted-plan boundary so M15-c can later
   check it against the goal; do not implement that guard in this milestone.
6. Onboard a disposable repository lacking `docs/MILESTONES.md`, confirm intent once, and
   observe a cold generated milestone dispatch and complete with Baton-recorded proof. The
   planning session must not perform that milestone itself.
7. Run §8, document the delivered interfaces, review, fix and close out.

**Natural split point after item 4.** Generation and conformance validation are coherent;
adoption, automatic seed and the live first-completion proof are the remainder. Record the split
under the plan rule; M12 is unfinished until both halves' acceptance holds.

## 8. Fixtures, verification, acceptance

- **Fixture-run:** missing plan, unusable plan, missing goal, correct generation, invalid cells,
  missing headings/slot, missing successor names, partial generation resume and duplicate
  completion; each twice, then `sh tests/run.sh`.
- **Manual, live:** a disposable owned Git repository with no plan, one intent confirmation,
  one planning session and a separate fresh milestone session; capture the latter's completion.
- **Acceptance:** the repository is onboarded, generates a conforming plan and briefs, and its
  first milestone dispatches and completes. No human plan review or hand-written seed is needed;
  all judgement and work stay on the subscription CLI.

## 9. Definition of done and evidence

Ten-item handoff with the repository's initial no-plan state, stored goal, generated files,
conformance output, session IDs and prompt sidecars, and accepted first-milestone proof. Identify
the planning and implementation sessions separately so one cannot masquerade as the other.

## 10. Risks and decisions this milestone settles

- **A fresh session cannot inherit a sibling.** The generation prompt must require repository
  paths and relevant facts in every brief, not “continue the previous plan” instructions.
- **Bootstrap can stall on omissions.** The initial handover and each generated close-out must
  name successors; plan eligibility alone is not a `run` disposition in the current relay.
- **Generation is not an approval loop.** The stored goal is the authority; validation fixes
  malformed output. Scope drift detection belongs to M15-c, not an invented person gate here.

## 11. Handoff and next milestone

Apply `CONTRACT.md` clause 3(c) to every refresh below: run `baton status` and check the
dispatch log for open lanes, including lanes absent from status; status also lists open parks. Refresh only a listed
milestone with neither an open lane nor an open park; still name every eligible milestone with its correct disposition.

The direct successors in the current graph are **M13 and M15**, paths `docs/milestones/M13.md`
and `docs/milestones/M15.md`, heading `Copy-ready session prompt`.

At close-out, after recording this milestone as done, re-read the plan's current Status cells,
dependencies and gates. List every direct successor in `eligible[]`, even if it cannot run yet,
and also every other milestone the plan then makes eligible. Derive each disposition at that
moment, with an open gate taking precedence:

- `held` — an open gate holds it; set `held_by` to that gate's exact name.
- `wait` — no open gate holds it and at least one dependency is not done; set `wait_for` to
  the IDs of all dependencies not yet done.
- `run` — every dependency reads done and no open gate holds it.

Use `docs/milestones/<ID>.md` and heading `Copy-ready session prompt` for each entry. Refresh
on main only listed prompts whose milestones have neither an open lane nor an open park with the goal/plan-adoption and generation-resume interfaces.
Compute from the live plan, not a predetermined disposition; never change dependencies or add
a gate to obtain it. M15's replan disposition uses M13's autonomous continuation when available,
but M13 is not an added entry dependency for M15. Baton initiates successors; this session does not.
