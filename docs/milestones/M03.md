# M03 — The tick under launchd

## 1. Identity

- **ID:** M03. **Objective:** The loop closes. `baton tick` runs the eight steps under the lock
  for every registered project and writes the marker; rows are reconciled; launchd runs it every
  minute through the granted shell; the Mac notification exists. After this milestone Baton
  dispatches Baton without a hand-run verb.
- **User-visible result:** `launchctl` shows `com.baton.tick` loaded; `baton status` prints a last
  tick under a minute old; M04 is dispatched by a tick, not by a person. A crash, a stall, a live
  question, a takeover and a gap each produce their event and their Mac notification.

## 10. Risks and decisions this milestone settles

- **Item 38 is the fact the `~/Documents` decision rests on.** TCC attributes access to the
  responsible process and its children inherit it, but the background service the tick starts
  detaches; whether a detached daemon keeps the attribution is exactly what the prototype did not
  test. If it fails, the fallback is deterministic and named above; do not paper over it.
- **The stall stat must include subagent transcripts** or every `/review-2` close-out reads as a
  stall: the parent sits on one Agent call for twenty minutes while its own file does not move.
- **A sleep is not a crash.** The prototype saw a row byte-identical across a 55 s suspend; the
  two-tick rule guards against a momentary read, not against sleep.
- **The takeover check is trusted only if item 45 passed in M01.** If it did not, log the
  comparison's result without standing off, and say so.
- **The marker's meaning is "a tick completed".** Writing it anywhere but last, after the lock,
  makes the gap report lie.
- **Whether `osascript` needs a fresh Automation grant for System Events under the granted
  shell** is observed on the first notification; the prototype saw no dialog for Messages.

### 6. Known limitations

- **A dispatch that fails for a permanent reason is retried every tick.** A `dispatch_failed` writes
  no `dispatch` event, so the lane does not open and the next tick tries again — one event per
  minute for as long as the cause stands. The designed bound is the second-consecutive escalation,
  which parks the lane, and that belongs to M05. Reaching it needs a brief on `main` with no fenced
  block under its heading, or a worktree or settings stage that fails; the close-out refresh writes
  the brief, and M04 and M05 are watched at the keyboard.
- **The cap is not applied, so every candidate a tick finds is dispatched.** Baton's own plan has one
  lane and its eligible set is one milestone at a time, which is the only reason this is safe. M06
  owns the cap and its order.
- **The stale-lock rule trusts a pid.** A lock past the interval whose pid answers no signal is
  cleared; if that pid has been recycled to an unrelated process the lock is left instead, and the
  relay waits for a person. The conservative direction was chosen deliberately.
- **`self_check_failed` records once per `(project, stage, detail)`** rather than every tick
  (D-041), so a plan file broken, fixed and broken again in exactly the same way logs once. The
  project is skipped every tick regardless, so nothing Baton does depends on the record.
- **The `question` escalation's guard is per milestone, not per session.** A lane that asks, is
  answered in place, and asks again within the same attempt escalates once, because nothing writes
  the `resolution` that would close the first. M05 closes it.
- **`status` re-reads the whole log twice per in-flight lane** for the live notifications, and the
  tick re-reads it once per check. At a log of hundreds of lines and a handful of lanes this is
  milliseconds; it is named because it grows with the log and nothing prunes one.
- **The CLI has moved to 2.1.269** while every document and every kickoff prompt names 2.1.268. The

`/review-2` with two reviewers in parallel, pinned to Fable, plus a hand pass over the same

The hand pass, run while the reviewers worked, found three of its own: REQ-TICK-05 was tested at one
stage of three (the `read` and `git` stages now have scenarios); `takeover-handback-pending` did not
actually prove the stand-off suppresses a stall (its transcript is now an hour stale, so it would);

Corroborated by both lanes and fixed:

- **A confirmed crash re-sighted itself every four minutes.** The two-interval window was applied to
  whichever sighting was newest, including the confirming second one, so a crash nothing had acted
  on yet wrote a sighting pair every four minutes — about 720 events a day — and `derive_ladder`,
  which counts every second sighting since the reset as a failure ending, would have read `escalate`
  off a single crash the moment M04 looked. A confirmation now stands until a dispatch or resume
  resets the attempt. Fixture `crash-confirmed-stands`.
- **A dispatch that failed was retried and logged every sixty seconds, unbounded and silent.** A
  `dispatch_failed` writes no `dispatch` event, so the lane never opened and the milestone was a
  candidate again on the next tick — for a launch-stage failure, one `claude --bg` spawn a minute all
  night. It also broke INV-05: two runs, two events. The second consecutive failure now parks the
  lane with a `dispatch-failed` escalation, which is the event table's own rule, and the park is what
  stops the retry. Fixture `tick-dispatch-fails-twice`.
- **The inbox was consumed against an empty listing when the listing could not be read.** Every rule
  in step 2 that reads "no live row" would then be true of every session: a handover a live session
  was mid-writing would be moved to `rejected/` as an orphan and its own rename would fail, losing
  it; an `asking` session would be recorded as already stopped. Nothing past the self-check now runs
  on a blind tick.
- **A blind tick still wrote the marker**, so the outage that caused it could never be reported and
  the only trace was a line a minute in `launchd.err`. Such a tick now returns 3 and writes no
  marker, and the gap report is what tells the person. Fixture `tick-no-rows` pins both.
- **`notify_text` capped after escaping, and capped bytes.** A cut landing between a backslash and
  what it escapes leaves the AppleScript literal ending in a lone backslash, which escapes the
  closing quote; osascript then fails and `notify` swallows it, so the longest messages were the ones
  lost. And this Mac's awk counts bytes even under a UTF-8 locale — measured, `printf 'a·b' | awk
  '{print substr($0,1,2)}'` yields `61 c2` — so the two-byte separator every composed message carries
  could be torn in half. The cap is now jq's, and comes first.
- **A failed self-check was a park nothing could see.** `derive_parked` reads escalations, so a
  project skipped every tick left nothing in `status`, and the once-only rule as first written meant
  a Full Disk Access grant revoked, re-granted and revoked again would notify only the first time.
  It is now a project-scope escalation of the log's own class, resolved by the first self-check that
  passes (D-041 rewritten). Fixtures `tick-self-check-{unparseable,unreadable,no-git,recovers}`.
- **The `baton-unhealthy` park could never be resolved**, so one stale lock would have shown as a
  project park forever and `derive_gap`'s "a gap with nothing to do is not one" would never be true
  again. The escalation and its resolution are now written in the same tick: Baton kept working past
  the condition, which is what separates a message from a park.
- **Two routes from a dispatched session to code the tick executes.** `git worktree add` runs the
  target repository's `post-checkout` hook, and a target's own `.git` is not in the deny list — so a
  hook written there would be run by a launchd job whose shell has Full Disk Access, which INV-12
  says never happens. And the launchd agent itself was not a named path, so a session could have
  chosen both the shell and the script the job runs. Both fixed (D-048).
- **The `sc_` prefix was shared by three functions** in a language where every variable is global.
  Renamed; no call chain overlapped today.

Raised by one lane and fixed: a session whose artifact was **rejected** was still sighted as a crash,
though the rejection had already parked the lane (fixture `crash-rejected-ended`); a handover entry
the consume **dropped** for a brief pointer not on `main` was still dispatched, because the archived
file keeps the entry — both are covered now by one rule, that a milestone with an open lane-scope
park is not a candidate; the **stale-lock break was check-then-act**, so two processes racing over
one dead lock could both have ended up holding it, and it is now a rename that exactly one can win;
step 6 read the **newest handover** rather than the newest that lists the milestone; the
once-only keys for a **question** and for an unscannable transcript ignored the session, so a second
attempt was silenced by the first attempt's open park; `crash_sighting` carried `state: null` where
the envelope says absent; a **`Remote: yes`** milestone would have printed a refusal every sixty
seconds until M07; `mtimes` was opt-in, so a scenario that forgot it was clock-dependent, and a
typo in it created an empty file rather than failing.

Declined, with the reason:

- **Adding `bin` to the deny list's Bash fragments.** D-026 excluded it deliberately and says why: a
  session runs `~/.baton/bin/baton status` from its start-of-session rules and a Bash rule cannot
  tell a run from a write. The `Read`/`Edit`/`Write` rules already name the directory; the Bash half
  is the stated limit of the class, which is "against the honest attempt, not an adversary".
- **Requiring a live lock-holder's process to name `baton` before leaving the lock alone.** It would
  let a wrong answer break a live holder's lock, which is the one thing INV-02 exists for, so the
  conservative test stays: a live pid means leave it. The reused-pid case is named in §6 and the
  printed line now says what to do about it.
- **Factoring the five per-lane loop prologues into one helper.** In `/bin/sh` such a helper sets
  globals, which is the hazard the prefix finding raised in the same review; the loops also differ
  in their guards.
- **Reading the log once per tick and threading it.** Named in §6 with its cost; it matters at tens
  of thousands of lines and the log holds hundreds.

### 6b. Known limitations, added after the review

- **A stale lock whose pid has been reused by an unrelated live process is never broken**, so the
  relay waits for a person. The conservative direction was chosen deliberately: the alternative
  tests are all capable of a wrong answer, and a wrong answer breaks a live holder's lock, which is
  the one thing INV-02 exists for. `lock_stale_report` prints the age and the remedy first, on every
  verb and every tick, so the condition is visible the moment anyone looks.
- **The deny list's Bash fragments still omit `bin`.** D-026 excluded it with its reason — a session
  runs `~/.baton/bin/baton status` from its start-of-session rules, and a Bash rule cannot tell a
  run from a write. The `Read`/`Edit`/`Write` rules name the directory, so the gap is a Bash
  redirect, which is the stated limit of the class: the rail is against the honest attempt.
- **A git-stage self-check failure parks with class `plan-unreadable`.** REQ-TICK-05 offers two
  classes and neither says "git"; the event's `stage` carries the precise fact and the class carries
  the scope. The alternative was a class outside the fixed list.
- **`derive_gap` orders events by comparing ISO strings**, which Baton writes with a local offset, so
  the ordering is wrong for events either side of a daylight-saving change. Pre-existing, raised by
  the review, and outside this milestone's files.
- **`launchd.out` and `launchd.err` are appended to and never rotated.** A quiet tick prints nothing,
  which is what keeps them small; a condition that prints every minute does not.
