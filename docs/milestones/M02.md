# M02 — The inbox and the log

## 1. Identity

- **ID:** M02. **Objective:** Consume the inbox the way the tick will, and land the whole of the
  dispatch log's schema — every event kind and all fifteen recovery derivations — before the tick
  exists, because the tick's first act is to reconcile from the log and every rule it runs is a
  derivation over it.
- **User-visible result:** A handover artifact dropped in `~/.baton/inbox/` is checked
  (provenance, `merged_as` against `main`, brief pointers on `main`), archived under its
  consumed-at name with a `consumed` event, or moved to `rejected/` with a `rejected` event and a
  lane escalation. `baton status` prints the one view from the log and the marker. Every
  derivation is a function with a fixture. The first milestone dispatched by Baton.

## 7. Implementation checklist (ordered)

1. `inbox_consume`: for each `*.json` in the inbox (never `.tmp`), `jq -e` parse; required fields;
   provenance by glob for the transcript; `project` registered; for `complete`,
   `git -C <path> merge-base --is-ancestor <merged_as> main`; each `brief` pointer's path and
   heading on `main` via `git show main:<path>`; `.tmp` orphans by `agents --json` rows without a
   `pid`. Reject with the rule's name; else archive as `<milestone>-<session>-<at>.json` and
   `log_event consumed` with `outcome`, `reason` or `error`, `written_by` (derived: `no-handover`
   → `stop-gate`, `api-error` → `stop-failure`, else `session`), `merged_as`, `blocked_by`,
   `archive` verbatim.
2. `asking` on consume: `"$BATON_CLAUDE" stop <id>` at once, so a later resume continues under the
   same id. `stopped`: route by reason to a table in `lib/stops.sh`'s place — for now the table
   returns the action's name and M04 attaches the action.
3. `lib/derive.sh`, one function per sentence of `docs/ARCHITECTURE.md` §6.4, each reading the log
   file, the rows file and the plan through the seams, each printing JSON; the fork chain
   (§6.1) as `current_session <project> <milestone> <attempt>`.
4. A fixture log per derivation under `tests/scenarios/derive-*/`, cut from `docs/ARCHITECTURE.md`
   §6.5's example lines and extended: a copy fork, two projects each with an M01, a wait with
   three retries, an unresolved escalation, a takeover then a hand-back.
5. `status_render` in the eight-line order of `docs/ARCHITECTURE.md` §5.3, whole file, no flags;
   the header line names the marker's value or "no tick yet".
6. `baton status` verb; `baton` with no verb updates its list.
7. The M01 artifact in the real inbox: `baton status` shows it un-consumed, then a hand-run of the
   consume function (exposed as `baton tick` only in M03; here a test entry point
   `sh tests/consume-once.sh` that takes the lock and runs step 2 alone) archives it and logs it.
   Confirm `merged_as` verified against this checkout's `main`.
8. `sh tests/run.sh`, `/review-2` pinned to Fable, `/address`, completion evidence, the handover.

## 10. Risks and decisions this milestone settles

- **`written_by` is derived from the reason, not stored on the artifact.** The gate and the
  StopFailure hook write the two reserved reasons; the session writes everything else; a
  session-written `no-handover` is rejected as not the session's word (REQ-ARTIFACT-04).
- **Derivation 3 reads a transcript.** It is the only reader of transcript content in Baton and it
  reads typed records' text only, through M01's `prompt_normalise`; if item 45 did not pass in
  M01, this derivation is written but its use waits (M03 gates on it).
- **The rows file.** Rows come from the seam as JSON; derivation 1 intersects with rows carrying a
  `pid`; `state` and `status` are not trusted for liveness (a crash reads `working` with
  `pid: null`).
- **The escalation message is not this milestone's.** A rejection writes the `escalation` event;
  the Mac notification for it is M03's `notify`.
