## 1. Identity

- **ID:** M02. **Objective:** Consume the inbox the way the tick will, and land the whole of the
  dispatch log's schema — every event kind and all fifteen recovery derivations — before the tick

## 10. Risks and decisions this milestone settles

- **`written_by` is derived from the reason, not stored on the artifact.** The gate and the
  StopFailure hook write the two reserved reasons; the session writes everything else. Settled by
  the milestone: authorship is not decidable from the file, because the hooks write artifacts a
  session could write byte for byte, so the reserved-reason rule bites only where it can — an
  `api-error` without the hook's `error` field is rejected, and a `no-handover` is recorded as the
  gate's whoever wrote it, which is the same handling either way (D-033, REQ-ARTIFACT-04).
- **Derivation 3 reads a transcript.** It is the only reader of transcript content in Baton and it
  reads typed records' text only, through M01's `prompt_normalise`; if item 45 did not pass in
  M01, this derivation is written but its use waits (M03 gates on it).
- **The rows file.** Rows come from the seam as JSON; derivation 1 intersects with rows carrying a
  `pid`; `state` and `status` are not trusted for liveness (a crash reads `working` with
  `pid: null`).
- **The escalation message is not this milestone's.** A rejection writes the `escalation` event;
  the Mac notification for it is M03's `notify`.

### 6. Known limitations

- **Authorship is not decidable from an artifact** (D-033). `written_by` is derived from the
  reason; a session that writes `reason: no-handover` is recorded as the gate's, because nothing in
  the file distinguishes them. Only the `api-error` half is enforceable, by the `error` field the
  hook alone can supply.
- `artifact_ids` splits a filename on its first hyphen, so a file named for a split milestone
  (`M02-b-<session>.json`) that does not parse would be recorded against `M02`. A file that parses
  uses its own fields and is unaffected.
- A tick killed between the move and the events leaves a file in `archive/` or `rejected/` with no
  event. The move leads deliberately: a file acted on twice would escalate a lane twice, and INV-06
  makes the move the decision. Derivation 4's `unrecorded` names such a file, so M03 has a field to
  act on rather than a silent state.
- The archive name's `<consumed-at>` and the `consumed` event's own `at` are two calls to the clock
  and can differ by a second under the real `date`. Nothing joins on them matching; the join is the
  `archive` field, and §6.4 now says so.
- A re-rejected file overwrites the earlier one in `rejected/`, so an earlier `rejected` event's
  `path` then names different content. REQ-ARTIFACT-06 says rejected files keep their name, so this
  is the spec's shape rather than an oversight.
- **The standing check held an empty directory, so it passed only where it was frozen.** A
  consume scenario leaves its inbox empty; git stores no empty directory, so the frozen
  `expected/` had an `inbox/` on the machine that froze it and none anywhere else, and
  seventeen scenarios failed the moment `main` was checked out fresh — which is what the
  merge did. `tests/run.sh` now prunes empty directories from both sides and diffs a copy
  of `expected/` rather than the checked-in tree. The same fault in one scenario
  (`dispatch-empty-deny`) was found and fixed at the start of this milestone; this is its
  general form.
- The `install` scenario asserts the canonical checkout's absolute path and its basename, so
  the standing check passes at `/Users/danny/Documents/Apps/Baton` and in its worktrees, and
  not in a clone elsewhere. Nothing needs it elsewhere today; the fix, when something does,
  is to substitute the checkout path the way `@TMP@` is substituted.
- `status` takes the lock like every other verb, so `baton status` run while a tick holds it exits
  75 rather than printing. That is REQ-VERB-01 as written.
- `BATON_TICK_SECONDS` in `lib/derive.sh` and the plist's `StartInterval` must be kept equal by
  hand until M03 writes the plist; M03's prompt carries the note.
- `lib/derive.sh` is 485 lines, of which about 340 are code and the rest the sentence each
