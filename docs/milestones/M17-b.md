`lib/derive.sh` prints keyed JSON, primitive values, transcript paths and returned failure data;
`lib/templates.sh` prints session names and delivered prompts. Neither needs conversion. Also
exclude hooks' JSON/statusline protocol and install-script output from this verb-rendering scope.
Do not decorate all shell stdout indiscriminately: that would corrupt the decisions consuming it.
Reproduce the inventory with `rg -n 'printf|echo|cat <<|jq -r' bin/baton lib/`, and classify every
site as person-facing, returned machine data, or persisted text. The new layer owns the first;
the other two categories are deliberate exclusions, listed in completion evidence.

**Design from those shapes.** Use a restrained monochrome base with one cyan emphasis for identity
and headings and amber for actionable state; normal text carries detail and dim text carries
secondary time/path metadata. Labels always carry meaning without colour. A quiet status remains
one short record; a busy status keeps the existing order. Align plan rows using the repeated fields;
give a long repair command its own indented continuation on a narrow terminal. Use consistent
spacing instead of panels, banners, animation, cursor movement or a dashboard. No model/session
control or read decisions enter the renderer. The useful distinction is what lane needs action
and what to type, not a decorative frame around arbitrary text.

The skill's substantive guidance, also the fallback if unreachable, is: choose purpose and tone
before coding; make typography and alignment establish hierarchy; choose a cohesive, restrained
palette and consistent status meaning; match density to the actual workflow; use borders only
when grouping requires them; retain readable monochrome/ASCII alternatives; and match complexity
to a small CLI. The project's plain-output and no-package requirements override the skill's
generic suggestions of animation, terminal frameworks and avoiding plain text.

**Terminal policy, POSIX shell and native tools only.** Determine stdout and stderr TTY status
separately with `[ -t 1 ]` and `[ -t 2 ]` at the verb boundary, before command substitutions or
pipelines. Pass that rendering context explicitly to helpers; do not rediscover a TTY inside
a pipe or force style because `/dev/tty` exists. Treat any set `NO_COLOR`, including empty, as
plain; ignore `FORCE_COLOR`; `TERM=dumb` or an unset TERM also disables decoration. Read a positive,
bounded decimal `COLUMNS` first, otherwise native `stty size` against the terminal only when
there is a TTY, otherwise default 80. Validate before shell arithmetic; invalid/zero/oversized
input falls back safely. No `tput`, terminfo package, terminal probing sequence or new dependency.
Use the effective `LC_ALL`, then `LC_CTYPE`, then `LANG` to allow UTF-8 decorations; unknown/C
locales use ASCII separators. Existing UTF-8 prose separators may remain in plain UTF-8 output,
which preserves the current fixtures; plain means no control sequences, not a forced transliteration
of data. Never truncate a path, identifier, timestamp, command or person's words to fit a width.
Below 60 columns, suppress table padding and place metadata/hints on indented continuation lines
on a TTY; an unbreakable path/command may overflow intact. Piped and NO_COLOR output keeps the
legacy single-line shapes regardless of width. Do not split UTF-8 bytes using this Mac's awk;
`notify_line` documents the existing code-point-aware jq boundary for Mac messages.

**One layer, no new decisions.** Every person-facing success, warning, error and Mac message
passes through `lib/render.sh`. Keep channel, exit status, record ordering, quiet behaviour and
the decision that chose the message at the caller. Capture raw tool diagnostics for the existing
log field; the terminal failure states Baton's need, observed failure and repair using context
already supplied by the caller, not a new error classifier. Keep the existing detail bounds:
dispatch detail is capped at 2,000 bytes with `detail_truncated`, not retained in full; event
lines still obey 4 KB. A failure renderer must never write the log or claim an event was recorded
when its writer refused it. Existing Baton-authored messages need no new wording.

## Completion evidence

### 1. What changed

- A new library, `lib/render.sh`, is the one layer between what Baton decides and what a person
  reads. It reads no file, writes no log, starts no process and decides nothing: the channel, the
  exit status, the order of the records and the decision that chose the message all stay at the
  caller. `bin/baton` sources it first and calls `render_init` once, at the verb boundary, before
  any pipeline.
- **Plain is the default and the contract.** Through a pipe, into a file, under `NO_COLOR`, or with
  a dumb terminal, every primitive emits exactly the bytes the caller's own format string produces.
  That is why this conversion is provable rather than argued: `tests/run.sh` redirects both streams
  to files, so all 319 pre-existing scenarios exercise plain mode, and **exactly two lines of
  frozen expectation moved in the whole milestone** — the same line twice, `render.sh` appearing in
  the directory listing `install.sh` prints (§4).
- **The stream is an argument at every call site.** `[ -t 1 ]` asked inside `$(…)` answers for that
  pipe and not for the stream the verb is writing to, so it is read once and passed down.
  `usage` alone is read on stdout by `baton help` and on stderr by every wrong-argument refusal, and
  now takes which one it is.
- On a decorated terminal: cyan for identity (lanes, milestones, headings), amber for what needs an
  act and for the command that resolves it, dim for a timestamp, path or session id, normal text for
  the detail. A label always carries its meaning as a word, so colour never says what a line *is*;
  it says, at a glance down a busy `status`, which lanes are waiting on the person.
- Below sixty columns a record's fields go onto indented continuation lines, split at the record's
  own ` · ` and **never inside a styled run** — `offline … message Baton · wake, or baton wake …`
  carries the wake session's name, which contains that separator, and a naive split sends a person
  after a session that does not exist. Nothing is ever truncated.
- `plan_render` takes the terminal as an optional third argument and stays plain without one,
  because `verb_dispatch` pipes it through `awk '$1 == id'` to show the one row it refused and
  colour in that first field would match nothing — the silent kind of wrong (D-050's shape).
- `lib/declared.sh`'s redispatch after two unfinished endings now says which readings changed
  rather than who changed them, the last of the three libraries D-134's rule was settled for
  (D-136 assigned this line to M17-b; D-144 records taking it).

### 6. Known limitations

- The `taken over` record's shape is `taken over  <lane> at <time>; hand back with <command>`, which
  carries no ` · `. Below sixty columns it therefore stays on one line and overflows intact rather
  than folding, which the brief permits for an unbreakable field. Splitting on `; ` as well was
  refused: details elsewhere carry semicolons mid-sentence and would fold in the middle of a thought.
- `render_record`'s label is the run before the first double space, capped at fourteen characters
  and rejected if it holds a separator or an escape. A future record whose label exceeds fourteen
  characters will render unstyled rather than wrongly; the longest today is `project park` at twelve.
- `baton status` and `baton plan` now fork more per line than they did, because each field is a
  command substitution. Both are hand-run verbs with no side effects and neither is on the tick's
  critical path; the tick's own records are few and its budget is sixty seconds.
- Styled mode composes each record through `$(…)`, which strips trailing newlines. No format
  produces a trailing blank line and `one_line` already cuts a carried question to its first line,
  so nothing is lost today; a future record whose last field genuinely ends in a newline would be.
