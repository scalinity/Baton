# M10-b — The tick's own clock, while it is working

## 1. Identity

- **ID:** M10-b. **Objective:** stop a tick reporting itself as an outage, and stop it advising a
  person to remove a lock it is holding.
- **User-visible result:** a completion whose standing check takes eleven minutes produces no
  "Baton was not running" message, and `baton status` during that check says a check is running
  rather than that the lock may be stale.
- **Size:** Small, about 1–2 hours; medium effort.

## 2. Dependencies and entry conditions

M10 complete and installed. M10 made the tick able to spend minutes inside step 2: it runs the
project's standing check itself, on a detached checkout of the commit a completion claims, under
the tick lock (D-148). Nothing else in Baton took that long before, so two rules that measure
against wall clock were never wrong until now.

## 4. Requirements, scope, non-goals

- **Covers:** the two person-facing statements M10 made untrue. Both were verified against the code
  rather than inferred, and the first is deterministic rather than a race.
- **The gap.** `derive_gap` measures `now − last-tick` at step 7. The marker is the *previous*
  tick's, written after that tick released its lock, so it is about one interval old when this tick
  starts. A proved completion runs the standing check inside step 2 — 652 s measured for Baton's own
  suite — so by step 7 the age is past two intervals. `dg_closed` then counts the `consumed`
  event this same tick wrote, whose `at` is after the marker, so `lanes > 0` and `report` is true.
  The first completion Baton proves with its own check therefore sends a Mac message saying the
  relay was not running for the length of the check it was running.
- **The stale-lock line.** `lock_stale_report` tells anyone running a verb during a hold longer than
  its threshold that the lock may be stale and can be removed if no verb is running. A verb *is*
  running, for up to `deadline_seconds`. `lock_stale_break` itself is safe — it checks `kill -0` —
  so the risk is a person acting on the advice, not Baton acting on it.
- **Scope:** measure the gap against the clock the tick started with rather than the wall clock at
  step 7, and say the holder is alive when it is. `tick_run` already captures `tr_now` at its top.
- **Non-goals:** moving the standing check out of the lock (D-148 settled that, and the state
  machine it would need is not this); a notification taxonomy change (M15's); rotating the log.

## Completion evidence

### 1. What changed

- **The gap is measured against the instant the reading is for, not always against `now`.**
  `derive_gap` and `gap_check` take an optional as-of that defaults to `now`, and `tick_run` passes
  `tr_now` — the clock it already captured at its top — to the reading it makes after its lanes.
  Nothing else changed shape: the marker is still the tick marker, the threshold is still two
  intervals, the key is still the marker value, and the closed-lane test still compares against the
  marker (**D-174**).
- **The defect this settles was deterministic, not a race.** Since D-148 the tick runs a target
  project's standing check inside step 2, under its own lock, for as long as that check takes — 652 s
  for Baton's own suite. The marker it measures against is the *previous* tick's, written after that
  tick released its lock, so it is already about an interval old when this tick starts; the check
  carries it past two intervals; and `dg_closed` counts the `consumed` event this same tick has just
  written, whose `at` is after the marker, so a lane is always open. The first completion Baton
  proved with its own check would therefore have sent a Mac message saying the relay was not running
  for the length of the check it was running.
- **The reported length is the outage's, not the outage's plus the check's.** The same two lines
  decide whether to report and what number to report. A real outage read from inside a long check
  now says how long Baton was actually not running.
- **A lock whose holder answers is reported as held, not stale.** `lock_stale_report` asks the
  recorded pid `kill -0`. When it answers, the line says the holder is running and offers nothing to
  remove; `stale lock  … if no verb is running, remove it` is kept for a holder with no pid recorded
  or a pid nothing answers for. `lock_stale_break` was already safe — it asks the same question and
  leaves a live holder alone — so what was exposed was a person acting on the advice, which a hold of
  minutes turns from theoretical into likely.
- **One tick reading deliberately stays on `now`**: the one on the path where `claude agents --json`
  could not be read, which returns before step 2 and so has spent nothing. Both normative documents
  now say which reading uses which clock rather than stating the rule unqualified (D-175).

### 6. Known limitations

1. **A launchd firing refused while a check holds the lock is still not an outage, and is still not
   recorded as anything.** That is D-148's accepted cost, not something this milestone changes; what
   it changes is that Baton no longer tells a person it was one.
2. **A tick killed mid-check leaves the previous marker**, so the next tick's gap includes the dead
   tick's working time as well as the outage. It over-reports rather than under-reports, which is
   the right direction for a report whose whole job is to be noticed, and it is D-115's behaviour
   unchanged.
3. **`kill -0` answers for a process this user cannot signal, and for `-1` or a process-group id.**
   A lock file holding such a value would be reported as held by a live holder. `lock_stale_break`
   has shared that semantics since D-039 and is the one that acts on it, so the two agree; the pid
   is written by `lock_take` as `$$`, and the deny rules keep dispatched sessions out of
   `~/.baton/`. Named rather than guarded, because diverging the two questions is what would be
   surprising.
4. **`derive_gap` still takes a rows argument it does not read**, and the as-of is now behind it.
   Every caller and fixture pins the signature, so it is left as it stands; the header says what
   each argument is.
5. **`derive_last_tick`'s `age_seconds` is computed and then not used by `derive_gap`**, which
   recomputes the age from the as-of. One extra `date` per gap reading, well under a `jq` spawn.
   `status` still needs it, so the function stays; derivation 8 now says how the two numbers differ.
6. **The as-of is a value, not a seam.** A caller that ought to pass one and does not gets `now`
   silently. There is one such caller and it is deliberate, with its reason at the line.
