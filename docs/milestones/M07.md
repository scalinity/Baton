## Scope

Implement remote operation behind the provider adapter only after observing actual supported-version behavior. Keep run, session, delivery and integration identities separate through remote starts and copy forks. Define the phone notification/privacy choice explicitly. Remote rows cannot be promoted to stronger liveness/ownership evidence than the provider supplies. Preserve local claim/release and fail closed during connectivity loss.

## Acceptance

Remote start/stop/resume losses reconcile by operation identity; settings/model restoration is observed; phone rulings cannot overwrite active human control; lost connectivity is unavailable, not completion or crash; copy-fork lineage cannot accept an obsolete session ending.

Run sh tests/run.sh and add behavior assertions for the new transitions. Use fault injection at
new effect boundaries, not only snapshot comparisons. Use two independent reviews and address
concrete findings. No build, live session, launchd or target-project operation is implicit in the
fixture test suite. Obtain any required explicit authorization before a live acceptance action.


## Cross-layer acceptance

- F-44: maintain an adapter conformance matrix for observation, launch, delivery, ownership evidence
  and remote capabilities. Unknown/unsupported capability fails before use, not after an assumed effect.
- Test delayed, duplicate, unavailable and schema-incompatible responses. Preserve operation/run
  identity through reconnect and copy forks; transport success alone is not delivery acknowledgement.
- Name the actual provider version, host, saved options and privacy/authorization boundary in live
  evidence. A successful local shim does not certify remote behavior or a new provider release.
- Keep provider-specific error/record parsing in the adapter. Policy consumes the normalized
  evidence; a provider must not choose scheduling or model changes through an opaque action label.

## Recovery procedure

Inspect existing code, durable action records, candidate work and prior evidence. Resume only the
unfinished part. Do not reset failure budgets, duplicate external effects, overwrite human work,
or weaken an invariant to make a continuation succeed. Split scope into a real plan row if needed.
