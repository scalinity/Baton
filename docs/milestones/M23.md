# M23 — A verb holding the lock is Baton running

## 1. Identity

- **ID:** M23. **Objective:** time any holder of Baton's lock spends under it, a verb as much as a
  tick, is never reported as "Baton was not running".
- **User-visible result:** `baton answer`, `baton onboard` or any other verb that holds the lock for
  a minute or more raises no `gap` message.
- **Size:** Small, about 1–2 hours; high effort.

## 2. Dependencies and entry conditions

M21 complete and installed: it measures a gap at the tick's start and reads a live holder from the
lock. Read its completion evidence, which records why it wrote no record of a skipped run.

## 3. Required reading

`CLAUDE.md`, `CONTEXT.md`, `CONTRACT.md`; M21's and M10-b's briefs and completion evidence;
`docs/DECISIONS.md` D-174 and M21's decisions (D-215 on); `docs/SPEC.md` REQ-ESC-10 and REQ-PERM-04.
Code, at the merged `main`: `lib/lock.sh` `lock_take` and the release; `lib/rows.sh` `gap_check`;
`lib/derive.sh` `derive_gap`; `lib/tick.sh` `marker_write`; `lib/permissions.sh` (the deny list's
names under `$BATON_HOME`).

## 4. Requirements, scope, non-goals

**The measured finding.** After M21 was installed (2026-10-01 20:30), three `gap` messages still
reached the Mac, each 120 s and assessed `unexplained` with a complete sleep history: at 22:30:30,
22:44:12 and 22:48:41. Each follows a lock held by something other than a tick for a minute or more,
per `~/.baton/launchd.err`: `lock held … (pid 80180, since 22:29:16)` while `baton answer M15-c`
stopped, settled and resumed a session; `(pid 93712, since 22:42:14)`; `(pid 75828, since
22:47:13)` while `baton onboard` ran its foreground judgment and waited for the person's yes. The
gap is measured from `last-tick`, which only a tick writes, so a verb's tenure reads as absence. M21
recorded the reason it wrote no record of a skipped run: the writer belongs in `lib/lock.sh`, a third
counted library at the time.

**Scope.**

1. **Every release is recorded.** When any holder releases the lock, it records the release time
   atomically in a file of Baton's own state that a dispatched session cannot write (the deny list,
   REQ-PERM-04, must cover it; place it under a name the existing rules already cover, or add it).
   The tick's `last-tick` marker keeps its meaning: the last completed tick.
2. **A gap is measured from the latest of either.** `gap_check` measures against the newer of
   `last-tick` and the last release, at the tick's own start (D-215), so a verb that held the lock
   through a scheduled run never opens a gap; a stale lock, whose holder does not answer `kill -0`,
   still reports as M21 made it.
3. **Status stays truthful.** `baton status`'s "last tick" line still names the last tick.

**Non-goals.** No change to the threshold, to host evidence, or to how a stale lock is cleared. No
verb waits for the lock instead of refusing; that is a separate change.
