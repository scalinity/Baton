# M13 — Autonomous handoff, and more than one at a time

## 1. Identity

- **ID:** M13. **Objective:** let close-out dispatch all newly eligible work up to the cap,
  without a human gate, and select reasoning effort from the brief's declared Size.
- **User-visible result:** an independent pair overlaps in time and its dependent successor
  finishes without human action; small work receives an appropriate effort through the existing seam.
- **Size:** Medium, about 3–4 hours; high effort for admission and parallel close-out correctness.

## 2. Dependencies and entry conditions

M12 complete and installed. A confirmed goal can already produce a plan, conforming cold-session
briefs and an automatically seeded first milestone. Dispatch already uses managed worktrees and
records baseline, changed paths and a Baton-produced check result. The existing cap and candidate
intersection remain the foundation. M15 can run independently after M12; it is not an entry condition.

## 4. Requirements, scope, non-goals

- **Covers:** SCOPE §6 M13 and §8 item 5; extends REQ-DISPATCH-01, -02 and REQ-TICK admission.
- **Scope:** automatic close-out-to-candidate progression; all newly eligible work up to the
  existing cap; independent branches overlapping; effort selected from the existing brief's Size
  declaration and passed to `claude_bg`.
- **Non-goals:** a second scheduler, changing genuine target gates without authority, budget
  pacing (M14), escalation classification or goal checking (M15), and cross-project dependencies.

## 6. Interfaces

- **Introduces:** Size-to-effort selection and automatic admission of the complete newly
  eligible set after close-out, using the existing dependency graph and cap.
- **Consumes:** `dispositions_in_force`, `dispositions_intersect`, `cap_order`, `dispatch_run`,
  `claude_bg <worktree> <name> <model> <effort> <settings> <prompt>`, plan Effort tokens and
  brief Size. Record the actual selected effort in the dispatch evidence.

## 7. Implementation checklist (ordered)

   A and B and C depending on both; record the current behavior and the gap to unattended execution.
2. Feed every newly eligible named milestone through the current intersection and cap. Keep
   explicit successor names in generated close-outs so no eligible work disappears into `omitted`;
   retain repeat protection, done filtering and dependency checks.
3. Make slot context and in-flight accounting include work admitted earlier in the same tick.
   An independent pair must get separate worktrees and correct parallel-run constraints; each
   close-out rechecks combined main before claiming completion.
4. Settle a deterministic mapping from declared Small/Medium/Large Size to supported effort
   tokens, how an explicit plan Effort overrides it, and the fallback for older briefs with no
   Size. Keep the existing model selection; do not build a new model router.
5. Run the fixture chain without a human action after its initial seed. Capture both start and
   completion times proving overlap, then C's completion after both dependencies.
6. Run §8, document the delivered autonomous continuation interface for M15's replan integration,
   review, fix and close out.

## 8. Fixtures, verification, acceptance

- **Fixture-run:** independent pair/join, cap one versus cap two, multiple eligible items,
  repeated close-out, successor omission, same-tick slot context, explicit effort override,
  every Size mapping and missing-Size fallback; each twice, then `sh tests/run.sh`.
- **Manual, live:** one disposable three-milestone project through Baton, with an independent
  pair and its join. After setup/initial seed no person starts, resumes, merges or approves a lane.
- **Acceptance:** all three milestones complete without human action, the independent pair
  overlaps, no cap is exceeded, and the selected effort reaches the existing dispatch seam.

## 9. Definition of done and evidence

Ten-item handoff with the fixture graph, start/end timestamps and session IDs, selected effort
and its source, handovers and verified merge/check records. A serial trace or mocked overlap is
not the live overlap proof; record unrun live work as unrun.

## 10. Risks and decisions this milestone settles

- **Eligibility is not a handover disposition.** The current relay escalates omitted names;
  preserve complete successor naming while making the chain automatic.
- **Parallel does not mean shared writes.** Separate worktrees and staged paths remain standing
  rules; the cap is a ceiling, not permission to ignore a declared conflict.
- **Effort precedence.** Explain Size mapping, explicit token overrides and legacy fallback
  in one place; later pacing must consume this seam, not invent another dispatcher.
