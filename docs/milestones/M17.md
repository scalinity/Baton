# M17 — Dispatch preconditions before worktree creation

## 1. Identity

- **ID:** M17. **Objective:** report the knowable dispatch defects together and refuse them
  before creating a milestone's branch or worktree.
- **User-visible result:** `baton plan <project>` names every unmet precondition for every
  eligible milestone, with a repair; dispatch refuses the same defects before worktree creation.
- **Size:** Medium, about 3–4 hours; **Effort: high**. Two existing library files:
  `lib/plan.sh` and `lib/dispatch.sh`. A small new shared module is permitted; a third existing
  library edit requires a further split before implementation, not an exception to the rule.

## 2. Dependencies and entry conditions

None. M17 is the single V1.1 root and the only milestone a person hand-dispatches. M17-b follows
it; M09 and M10 follow M17-b. The V1 relay is installed. Read the live plan and status first;
eligibility and a lane's park are different facts. Do not dispatch this milestone or any other
from an authoring session.

The authoring baseline at `e165c75` was measured in the canonical checkout with
`LC_ALL=en_US.UTF-8 sh tests/run.sh`: **246 scenarios, 0 failed**. This is a starting point,
not implementation acceptance. D-099 establishes that linked worktrees resolve the canonical
checkout through `install.sh`, while a detached clone cannot satisfy the two install scenarios'
absolute-path assertions. Use the canonical checkout or its linked worktree; do not relax those
assertions or promise detached-clone portability here.

## 4. Requirements, scope, non-goals

**Already built; extend it.** `7dd3ee6` made `prompt_from_brief` distinguish a brief absent
everywhere, present on disk but absent from `main`, and on `main` without a complete fenced
block at the requested heading. Each message explains the need and names a commit command.
`dispatch_one` also refuses a worktree without a readable copy of its own brief. The scenarios
`dispatch-brief-absent`, `dispatch-brief-uncommitted` and `dispatch-worktree-missing-brief`
pin these cases. The existing guard runs **after** `worktree_ensure` and `settings_compose`;
it prevents a bad session, but still leaves creation side effects. Do not rewrite working code
or its useful messages to match a preference.

**Remaining work.** Share one read-only dispatch-precondition result between `verb_plan` and
`dispatch_one`. Put it in a new `lib/preconditions.sh` if needed to keep the existing modules
small; source it from `bin/baton` and `tests/lib-load.sh`. It may call `prompt_from_brief` after
the libraries have been loaded. It must not copy that parser or call `worktree_ensure`,
`settings_compose`, a verb, or a session operation. Its checks are:

1. The registered checkout has a usable `main`, and the milestone's brief is readable from
   `main` at `Copy-ready session prompt` with the complete fenced block the dispatch reads.
   Use the existing three-case messages. The slot paragraph must also be replaceable: run the
   existing `slot_line` validation without creating a worktree. A missing slot is knowable now.
2. Each literal `docs/…` reference in that fenced kickoff prompt exists on `main`. Inspect the
   fenced prompt, not the whole explanatory brief or its historical evidence. Deduplicate paths;
   remove Markdown delimiters and sentence punctuation, preserve the path's spelling, accept
   an explicitly named directory only when Git has a tree there. Template examples such as
   `docs/milestones/<ID>.md` are not literal filenames. Expand finite brace alternatives if a
   real prompt uses them; never evaluate shell text or silently discard an ambiguous reference.
   Report an ambiguous reference as needing a concrete path. Do not recursively follow links.
3. If the milestone branch already exists, it contains the latest commit on `main` that changed
   the milestone's brief (`git log -1 main -- <brief>`), verified by ancestry against that branch.
   Also require a readable brief in an existing milestone worktree. Check the actual worktree
   HEAD when it exists, not merely the expected branch name. A readable old copy alone does not
   prove the brief's commit arrived. Do not require every unrelated `main` commit to be merged,
   demand a clean worktree, discard edits, or forbid a later branch-local completion-evidence edit.
4. The project's `permissions.json` is present and parses, and satisfies the existing
   `settings_compose` deny-rule guard. Inspect without composing or writing settings. Do not
   widen the allowlist, invent new deny classes, or count bypass mode as a substitute for them.

Use `plan_eligible` unchanged to choose the milestones for the report. Preserve the current
plan parser and all Model-cell validation; a plan that cannot parse still reports its existing
parse failure rather than inventing an eligible set. For a parsed plan, collect every independent
failure for each eligible milestone in plan order, then emit the whole report. An unreadable
prompt prevents inspecting its references; report that dependency once, not guessed filenames.
Still check its branch and permissions. A shared permissions defect names every affected milestone.
Runtime rows, holds and cap continue to govern admission in their existing callers; the report
does not turn plan eligibility into a promise of dispatch or alter any of those decisions.

Each diagnostic names the milestone, what Baton needed, what it found and one concrete repair
command. Reuse the existing add-by-name/commit command for a brief after the named authoring fix;
use `git -C <worktree> merge main` for a stale checked-out branch, with no automatic merge.
For a branch with no worktree, name the branch and a deliberate checkout/worktree-and-merge repair;
never advise a forced reset. Missing referenced documents need authoring/restoration before their
named add/commit command. For permissions, point to the exact file and an editor command to
restore the owner's deny rules, not an invented permissive JSON value. Quote every path as shell
data, including apostrophes and spaces; suggested commands are printed and never executed.

The plan verb remains read-only, prints its graph and widening provenance, appends the complete
precondition report, and returns 1 if any precondition failed, 0 otherwise; retain its existing
registration/parse error codes. `dispatch_one` checks the same result **before**
`worktree_ensure`, including on redispatch. On failure it records through existing
`dispatch_failed` with the applicable existing stage (`prompt`, `worktree`, or `settings`) and
returns failure. Check all defects for the report; the existing single failure event may carry
the first defect deterministically. No new event kind or stage is needed. Keep the later
readability guard as a final race check unless its removal is proved safe, not merely redundant.

**Creating nothing** means no new branch, worktree, settings file, prompt sidecar, session or
caffeinate process. The lock and existing failure log/escalation machinery still operate.
Do not claim the failed command writes no event. Do not turn this precheck into a standing-check
run: running a project's tests is not a dispatch prerequisite owned by M17.

**Explicit deferrals.** Leave `dispatch_try`'s retry-then-escalate bound untouched, including
precondition failures; first-occurrence escalation is for M15 to classify. D-098's unification
with `brief_pointer_check` is deferred, despite its older assignment to M17. Do not edit
`lib/inbox.sh`, change its archived detail strings, or migrate existing archives. Rendering is
M17-b. No new verbs, dependencies, packages, plan format, on-main rule, event-log line format,
or unrelated dispatch/admission decision changes. D-101/D-102 are findings, not permission to
add pause machinery or change the source from which the plan is read.

## 6. Interfaces

- **Introduces:** `dispatch_preconditions <project> <milestone>`: read-only, one JSON result
  with an ordered `failures` array; each failure carries its existing dispatch `stage`, a stable
  check name, the affected path and the human detail/repair. Successful inspection returns the
  same shape with an empty array. Distinguish a failure to collect the result from a valid result
  naming unmet preconditions; never treat empty or malformed output as success. Settle exact
  field names in implementation and carry them into ARCHITECTURE and M17-b's prompt.
- **Consumes unchanged:** `plan_of_project`, `plan_eligible`, `project_path`, `prompt_from_brief`,
  `slot_line`, `dispatch_failed`, branch/worktree naming, `settings_compose`'s deny guard.
- **Preserves:** all machine-return values and the event writer. Render human text only at
  the plan/dispatch boundary; no terminal styling in shared data or stored log fields.

## 8. Fixtures, verification, acceptance

- **No-build:** inspect the diff and count existing library edits; confirm no call path to
  worktree/settings/session creation precedes the check. Inspect committed brief and branch
  ancestry, not just filesystem presence. Run the standing check under `LC_ALL=en_US.UTF-8`.
- **Fixture-run:** multiple eligible milestones, multiple independent defects on one milestone,
  shared permissions failure, and a valid eligible peer all reported in one pass; noneligible,
  held and done rows unchanged. Cover absent/on-disk-only/malformed-fence/missing-heading/missing-slot
  briefs; valid/missing/deduplicated/template/ambiguous documentation references; empty/malformed/
  missing permissions; no branch, stale branch with no worktree, stale readable brief, missing
  worktree brief, current branch with retained local work, and a successful dispatch.
- **No-creation proof:** snapshot refs, worktree inventory, settings, sidecars and shim calls
  before and after each precondition refusal. The only expected state changes are the existing
  failure record and, on the second tick, existing escalation/notification state. No Claude start
  or caffeinate call. Run each fixture twice, including the repaired case and transient launch failure.
- **Existing behaviour contracts:** retain `plan-*` parse/eligibility checks, live-row refusal,
  slot replacement, settings deny guard, session names/argv, log schema, retry bound and all
  `reject-brief-pointer` archive behaviour. Keep `tests/run.sh`'s full diff and both runs.
  The intentional timing correction changes old expectations that contain settings/worktrees
  created before a brief refusal. In `dispatch-worktree-missing-brief/cmd`, replace its assumption

  remains absent; preserve the unchanged branch assertion and add a separate pre-existing-worktree

- **Manual, read-only:** `baton plan Baton` and a fixture plan with several failures. No real

- **Acceptance:** the complete report names every inspectable unmet precondition; the earliest

## 10. Risks and decisions this milestone settles

- The live plan is read from the working tree while briefs come from `main` (D-102). This check
  limits damage when the two disagree; it does not make publication atomic or add pause (D-101).
- A missing prompt limits what references can be inspected. Report that limitation rather than
  declaring the milestone ready or inventing its dependencies. Quote repairs, never execute them.
- Git ancestry and readable worktree content answer different questions; test both without
  requiring unrelated new main commits or destroying resumable work.
- `dispatch_failed` caps detail at 2,000 bytes and marks `detail_truncated`; `log_event` refuses
  lines over 4 KB. Preserve those bounds. The older scope's claim that stderr was kept in full
  was wrong. Do not introduce unbounded aggregate diagnostics into one event.
- First-failure escalation belongs to M15; D-098 remains deferred. Record implementation
  decisions at the next free D-number, without quietly taking either scope back.
