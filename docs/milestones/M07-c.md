# M07-c — The Mac message: Claude's icon, and a click that opens the session

## 1. Identity

- **ID:** M07-c. **Objective:** the Mac message Baton raises for a park or a notification carries
  Claude's icon and, when clicked, opens the session it is about in Claude.app — instead of arriving
  as Script Editor's notification and opening a blank AppleScript document.
- **User-visible result:** an escalation or notification appears under a "Baton" sender with Claude's
  icon; clicking it opens the lane's session in Claude.app's Code tab (or, with several open, the
  newest park's session, or Claude.app's own "needs input" view — whichever §7 item 1 settles).

## 2. Dependencies and entry conditions

M07-b complete and installed (both edit `install.sh`, so they run one after the other). Every
dispatched session is on Remote Control (D-081), so every session has a claude.ai session id.

## 4. Requirements, scope, non-goals

- **Covers:** REQ-ESC-02 (how the Mac message is raised), REQ-SETUP-05 and 08 (what the install
  builds and the one notification permission a fresh Mac grants), SPEC §4 item 7 amended to let
  Baton read one more thing from a transcript — the newest `remote_session_change` URL.
- **Scope:** a notifier applet built by `install.sh`; `notify` posting through it; the click opening

- **Non-goals:** a third-party package (`terminal-notifier` and the like); committing Claude's icon

  stays).

## 7. Implementation checklist (ordered)

1. Measure before building, live, with the person at the Mac: (a) a notification posted by an applet
   built with `osacompile` shows the applet's name and icon, not Script Editor's; (b) clicking it
   launches or activates the applet, and the applet can tell a click launch from a post launch; (c)
   `open 'claude://code/session_<id>'` opens that Remote Control session in Claude.app — the app
   gates it behind a feature flag — and `https://claude.ai/code/session_<id>` is the fallback; (d)
   what the first notification from a new applet asks macOS for. If (a) or (b) fails, stop and ask the
   person in the session with `AskUserQuestion` (D-089): the fallback is a small Swift helper using
   `UNUserNotificationCenter`, which is D-005's named moment and a build step, so it is the person's
   call.
2. The applet: on launch, post every spooled message and record each one's target; on a launch with
   nothing spooled — a click — open the target of the newest message still standing, or
   `claude://code/needs-input` when there is none.
3. `install.sh`: build `~/.baton/bin/Baton.app` from `notify/Baton.applescript`, copy
   `/Applications/Claude.app/Contents/Resources/electron.icns` into it when that file exists (and keep
   the applet's own icon when it does not), set a bundle identifier, sign ad hoc, idempotently.
4. `notify`: spool the message with its target and launch the applet; keep `osascript` as the path
   when the applet is missing, so a failed install never silences the relay.
5. `session_url`: the newest `remote_session_change` URL in the session's transcript, found by the
   same glob derivation 3 uses; SPEC §4 item 7 and a decision entry say so.
6. The fixtures, twice each: a message with a session URL, one without, the applet missing.
7. `sh tests/run.sh`, `/review-2`, `/address`, completion evidence, the handover.

### The rulings

Asked in this session with `AskUserQuestion`, the recommendation chosen for both:

1. **What a click opens when several messages stand:** the session of the newest message Baton posted,
   whichever was clicked, and `claude://code/needs-input` when that message names no session.
2. **What a click does to Notification Center:** it clears every Baton message, because clearing only the
   clicked one is not possible; older parks stay in `baton status` and Claude.app's sidebar.
