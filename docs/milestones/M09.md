# M09 — Where sessions live, and how they surface

## 1. Identity

- **ID:** M09. **Objective:** create new worktrees under Baton's home, preserve every existing
  recorded session path, and put dispatched sessions under their project in the desktop sidebar.
- **User-visible result:** new worktrees use the managed root; existing branches and dirty work
  survive; sessions remain resumable and appear under their project rather than Other.
- **Size:** Small, about 2–3 hours; medium effort. Host investigation is the uncertain part.

## 2. Dependencies and entry conditions

M17-b complete and installed; M10 can run independently. The existing V1 relay is installed. Inspect the
host's `claude --help`, worktree inventory and session rows before choosing a grouping mechanism
or relocating a working directory. This milestone does not depend on M10's new completion fields.

**Kickoff:** M09 is not a root. It depends on M17-b, and M17-b's close-out lists it with disposition
`run`, so the tick admits it — nothing about M09 is hand-dispatched, as SCOPE §7 specifies. M10 is
M09's sibling under the same parent, admitted by the same handover; this M09 session does not start
or restart M10 and does not assume which sibling will finish first.

## 4. Requirements, scope, non-goals

- **Covers:** SCOPE §6 M09 and §8 item 2; REQ-DISPATCH's worktree rules and D-078's
  continuation guarantee.
- **Scope:** `$BATON_HOME/worktrees/<project>/<milestone>` for new attempts without an existing
  owned worktree; existing attempts use their recorded paths, including legacy sibling paths.
  Preserve every branch and dirty worktree. Relocate a session-bearing worktree only after a
  disposable fixture proves a supported same-session stop/resume mechanism and correct writes
  at the new path. Otherwise keep the legacy path and record that limitation. Actual desktop
  grouping remains required.
- **Non-goals:** deleting worktrees or branches, changing saved transcripts, a new session manager,
  completion-proof strengthening (M10), non-Git projects, or a language rewrite.

- **Consumes:** `worktree_ensure`, `claude_bg`, the existing dispatch record, Git worktree
  metadata and associated session identity. M10 may land before or after this milestone.

## 7. Implementation checklist (ordered)

1. Inventory existing Baton and probe worktrees: repository identity, branch, HEAD, dirty state,
   recorded dispatch path and associated session.
   Include `Probe07b`, `Probe07g` and `BatonProbe`; identify ownership before moving anything.
2. Read `claude --help` on the host. Test the supported project designation or cwd arrangement
   with one disposable fixture session. Verify both desktop grouping and writes landing in its
   worktree. Record CLI version, invocation, cwd, observed grouping and actual write location.
   A changed filesystem root alone does not satisfy grouping.
3. Create new attempts without an existing owned worktree under the managed root. Existing
   attempts keep their recorded paths. Verify reuse is the intended linked worktree of the
   registered repository on the intended branch; refuse unrelated repositories or wrong branches.
   Add fixtures for new dispatch, managed and legacy reuse, and probe naming.
4. On the disposable fixture, prove a supported relocation mechanism preserves the same saved
   session's stop/resume behavior, settings, transcript association and writes at the new path.
   Git's successful move alone is not that proof. Never edit Claude's private databases.
5. Only after that proof, relocate owned session-bearing worktrees with branches and dirty
   changes intact. If it cannot be proved, leave their recorded paths valid and record the
   limitation; do not delete, reset or silently recreate them. Capture before/after inventories.
6. Update the standing worktree wording, verify §8, review, fix and close out.

## 8. Fixtures, verification, acceptance

- **No-build:** compare worktree inventories and branch refs before/after; inspect the actual
  `claude --help` output and the selected mechanism.
- **Fixture-run:** managed creation/reuse, legacy recorded-path reuse, wrong-repository and
  wrong-branch refusals, preservation of branches and dirty changes, and probe naming;
  each twice, then `sh tests/run.sh`.
- **Manual, live:** one disposable probe dispatched through Baton; capture its sidebar project
  grouping and its actual working tree. Capture same-session continuation evidence for any
  supported relocation; otherwise record that capability as unproved and keep legacy paths.
- **Acceptance:** new worktrees use the managed root; existing recorded session paths remain
  valid unless a supported relocation is proved. Branches and dirty changes survive unchanged;
  wrong-repository and wrong-branch reuse are refused; no worktree is deleted. Grandfathered
  paths are an explicit limitation, not successful relocation. The dispatched session groups
  under its project; separate proved behavior from unresolved grouping or relocation capability.

## 9. Definition of done and evidence

Handoff per `docs/MILESTONES.md`'s ten-item template, with CLI output, sidebar capture, inventories,
branch hashes and continuation evidence. Do not substitute a proposed grouping flag for a live proof.

## 10. Risks and decisions this milestone settles

- **Grouping may not be exposed.** D-086 found it not settable by a session. Inspect the current
  host and record the result; if no supported approach meets acceptance, report it unfinished.
- **Relocation can strand a saved cwd.** Keep the recorded path unless the disposable proof
  establishes supported same-session continuation. Unproved relocation leaves a stated limitation.
- **Grouping and filesystem acceptance are separate facts.** Any decision to separate them must
  explicitly amend SCOPE and M11's entry conditions; never claim unsupported grouping passed.
