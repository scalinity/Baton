## 6. Interfaces

- **Introduces:** completion `baseline` (dispatch commit), `changed_paths` (Git-derived changes
  from the frozen candidate) and `check_result` (Baton-produced outcome, exact checked revision
  and evidence pointer), bound to the attempt, candidate and integration commit identities.
- **Consumes:** dispatch commit/branch/worktree record, brief §4 declared scope and §5 proposed
  files, `artifact_check`, `consume_one`, existing `merged_as` verification and repeat detection.

## 7. Implementation checklist (ordered)

1. Show the limitation with a fixture naming the repository's first commit as `merged_as`;
   keep a valid completion fixture beside it. Add a branch with no change in declared scope.
2. Require one bound chain: recorded attempt → dispatch baseline B → frozen candidate tip T →
   integration commit M (`merged_as`) → checked revision V. Resolve and record immutable commit
   identities: B from that attempt's dispatch, T from its recorded branch, and M from the claim.
   Require B to be an ancestor of T, T to be an ancestor of M, and M to be on main. Freeze T
   before deriving evidence; later branch movement must not substitute a different candidate.
   V must be M or a descendant of M on main, and the check result must name that exact revision.
   Reject a disconnected chain even when M descends from B and a separate branch has scoped work.
3. Derive changed paths from that same frozen T against B, excluding unrelated parallel work
   on main; never inspect a moving branch independently to justify M. Settle how the declared
   scope is read from the existing brief without making the proposed file list an invented
   exhaustive allowlist. Reject no in-scope change.
4. Have Baton execute the project's standing check on the tree at V and record its exact commit,
   actual result and output pointer with the same attempt/B/T/M evidence. Establish that the
   checked tree really is V; do not label an unverified or changing checkout with a sampled HEAD.
   A session-provided success string cannot satisfy this check. Preserve the
   existing broken-main behavior when the standing check fails.
5. Define the additive record enrichment and treatment of pre-M10 archived artifacts and already
   dispatched attempts. Keep repeat detection stable: re-delivery cannot dispatch or recheck twice
   just because Baton added evidence to the archived record.
6. Run §8, update the contract and interface documentation, review, fix and close out.

## 8. Fixtures, verification, acceptance

- **Fixture-run:** unrelated ancestral commit, wrong baseline, unchanged branch, only
  out-of-scope changes, B with an in-scope T but unrelated M on main (T not merged), candidate
  branch movement after freezing T, mismatched checked revision, valid scoped change,
  unrelated parallel main changes, session-forged
  check success, real check failure, valid Baton-produced result, and enriched-artifact repeat;
  each twice, then `sh tests/run.sh`.
- **Acceptance:** an unrelated ancestral commit is rejected; a branch changing nothing in
  scope is rejected; unmerged T is rejected even when M descends from B. Accepted records bind
  the recorded attempt, B, frozen T, M and exact checked V, with scoped changes from B to T and
  a result actually produced by Baton on V. Existing valid completion and repeat behavior hold.

## 9. Definition of done and evidence

Handoff per the ten-item template, including the failing-before/passing-after false-commit proof,
Git ancestry/diff output for B/T/M/V, the recorded check command, exact checked revision, exit
outcome and output pointer, and a valid enriched completion. A session's statement that tests
passed is not the required evidence.

## 10. Risks and decisions this milestone settles

- **Proposed files are not exhaustive scope.** Record a small, deterministic scope declaration
  convention compatible with the existing brief, including documentation-only milestones.
- **Parallel main moves.** The branch diff must prove this milestone's changes, not another's.
- **Additive records and repeats.** Existing archive meanings remain intact; settle upgrades
  without allowing an unproved new claim or replaying an already consumed handover.
