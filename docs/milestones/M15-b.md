- **User-visible result:** a sleep-explained gap is recorded and visible in status without a Mac
  notification; an unexplained outage still notifies; a dead lane uses existing recovery.

## 4. Requirements, scope, non-goals

Implement M15 §4's finding. Preserve threshold, marker deduplication, audit events and hardware
constraints. Introduce no new liveness probe, session ping, model judgement, sleep-prevention
workaround, root helper or power-management daemon. No real Mac sleep is needed for acceptance.

**Host evidence contract.** Read `/usr/bin/pmset -g log` once per needed tick through an injectable
command/input seam. Fixtures supply raw history, exit status and the measured gap. Parse actual
Sleep/Wake/DarkWake events with numeric UTC offsets into epochs; ignore Wake Requests, assertions
and summaries. Sort/deduplicate identical transitions; reject contradictory same-time transitions
and unaccounted boot/clock boundaries. Pair Sleep with the next Wake **or DarkWake**, treating
DarkWake as awake, never assuming the whole lid-closed period was continuously asleep. The parser
must retain sufficient boundary history to establish state at the marker and history through the
sampled endpoint. A successful command with empty or partial history does not prove no sleep.

**Coverage policy.** Let the interval be `[epoch(marker), sampled_endpoint]`, with endpoint captured
consistently with `gap_seconds`, not the later event-write time. Clip proven sleep intervals to
this window. Require a complete, unambiguous state timeline and some proven sleep. Classify
`HOST-EXPLAINED` only if every continuous awake portion (including the portions before sleep and
after wake) is **strictly less than two tick intervals**. This reuses the missed-tick threshold;
short dark wakes and tick latency do not require impossible literal coverage of both endpoints.
Do not subtract all sleep and sum disconnected awake fragments: separate short dark wakes are
not one long scheduling opportunity. Any awake portion at least two intervals remains
`UNEXPLAINED`, even if some sleep overlaps. This is a bounded explanation policy, not proof that
the relay was healthy during sleep. Fresh reads must establish the trailing state; an unmatched
Sleep at the history boundary alone cannot prove coverage through now.

**Unknown is not asleep.** Unreadable, failed, truncated, malformed, ambiguous or insufficient
history yields unknown evidence. Record the reason and keep the gap notification, explicitly
saying sleep history could not explain it; do not claim that the host reported no sleep. Complete
history with no sleep or enough awake time yields UNEXPLAINED and notifies. If the measured host
source ceases to support reliable attribution, document that plainly and retain this fallback;
do not replace evidence with a guessed cause or silence all gaps.

**Audit and delivery.** Both outcomes write the gap event under the existing single writer and
marker key, once. Retain duration, marker and detail; add disposition, measured endpoint and
bounded supporting sleep/awake evidence or unknown reason. HOST-EXPLAINED skips Mac delivery,
not event creation. Update SPEC/ARCHITECTURE to distinguish a recorded notification-class event
from actual delivery. `baton status` must show the latest recorded gap with its disposition and
time after `last-tick` advances, while retaining the current active-gap view without duplicating
that same marker. It must not notify or reread host history to display an existing record.

**Wake reconciliation.** Reuse the normal tick pipeline, not a second walker/ladder:

- Consume the inbox first. Read `claude agents --json` successfully; a failed listing is unknown,
  not an empty list, and must not produce crash sightings or dispatches.
- Use `derive_in_flight` and existing `takeover_check`/stand-off protection. A candidate has an
  absent row or `pid: null`, not merely `state: working`, stale output or “not connected.” Honor
  `inbox_holds`, `ended_on_disk`, consumed/rejected endings, current attempt/session and the
  dispatch/resume grace of two intervals. Parked/waiting/closed lanes are not new crashes.
- Death is the existing `crash_check` confirmation: two distinct tick sightings within two
  intervals, after the most recent dispatch/resume. A pre-sleep first sighting older than that
  expires; wake starts a new pair. A live pid and unchanged row across sleep is not a crash.
- Reuse transcript and subagent mtime checks for progress, and transcript readability/takeover
  guards. Age accumulated during proven sleep alone must not produce a wake-time stall message:
  use the same proven sleep intervals when assessing eligible awake inactivity against the
  existing stall threshold. Genuine awake inactivity still follows the existing stall route,
  separately from death. An unreadable transcript remains unknown/protected, not dead.
- Feed a confirmed death through existing `stops_run`/`ladder_step`: `transcript_of` decides
  flagless resume versus redispatch when the transcript is missing; it does not itself decide
  death. Preserve one resume, one redispatch, then actionable escalation. Do not notify merely
  because the host woke, immediately escalate the first missing row, or double-act on recovery.
  Actual credential/access or other existing actionable errors retain their normal routing.

D-078's missing-directory crash motivates this check but does not prove a sleep-caused crash.
No session restart is authorized merely by observing a gap.

## 8. Fixtures, verification, acceptance

Use fixture history, gap, clock, rows, transcripts and a notifier spy; never sleep a real Mac.
For the same open lane and qualifying gap, assert one recorded event in each case and:

- Covering sleep with short awake margins/dark wakes: HOST-EXPLAINED, **zero notifier calls**.
- Complete awake history/no sleep: UNEXPLAINED, **one notifier call**.
- Partial overlap leaving >= two intervals awake: still one call; exactly two intervals is not silent.
- Failed read, empty/truncated history, missing boundary, malformed offset, conflicting transitions,
  reboot/clock discontinuity: unknown with recorded reason, one call. Wake Requests alone explain nothing.
- Multiple sleeps, offset changes, duplicate records and short dark wakes parse deterministically;
  marker + duration differs from event.at without changing the assessed interval.
- Second evaluation of the same marker creates no second event or message for every outcome;
  after marker advances, status still displays the recorded explained gap. A new qualifying gap re-arms.
- Live pid plus unchanged transcript after sleep: no crash and no sleep-only stall. Sufficient
  awake transcript inactivity still follows the existing stall check, not the crash ladder.
- Missing/null-pid row on one wake tick: no recovery; second qualifying tick: existing ladder once.
  Expired pre-sleep sighting cannot confirm on first wake tick. Missing transcript selects redispatch
  only after confirmed death; present transcript selects resume. Failed rows read, takeover,
  unscannable transcript, inbox artifact, consumed/rejected ending and closed lane keep their guards.

Run scenarios twice and `sh tests/run.sh`. Acceptance includes silent and notifying outcomes,
audit/status persistence, confirmed-death recovery and no real sleep. A live read-only LaunchAgent
probe can confirm access; it is not a replacement for deterministic fixtures.

dark wakes can run ticks. A stale transcript is not a dead process. Do not suppress an unrelated
awake stall, count sleep as inactivity, or manufacture a person action for expected hardware behavior.
